How registration is verified against the school's records

  1. The person picks Student or Faculty / Employee and enters their school number. The server checks the format, then looks it up in student_records or employee_records and checks that the record may register (enrolled / on leave; active / on leave).
  2. The name is shown from that record for confirmation. On submit the number is looked up again on the server, so the account type and name always come from the record.
  3. The account (users, role always user) stores the number in users.student_number or users.employee_number: a foreign key to the record and a unique key, so one school number can belong to one account only. A CHECK constraint allows at most one of the two.
  4. Design choice: the first and last name are copied into users at registration, because staff and administrator accounts (which have no school record) and old accounts need a name too, and history must keep the name the account had. The birth date is not copied: it stays only in the reference record and is read through the foreign key to reject passwords containing it. School emails also stay in the reference tables.

Status model (no duplicate status systems)

  • claims.status is the main claim status: pending → approved (approved for collection) → verified (identity checked at the desk) → returned. A rejection does not change it: the claim stays pending.
  • The current review outcome is the latest claim_reviews row (approved / rejected); there is no separate outcome column that could disagree with the history. Every decision is a new row with its reviewer, reason, previous outcome and time.
  • found_items.status keeps its three values; returned and disposed are the two final outcomes. The return record is on the item (returned_at, returned_by, return_claim_id, unique), the disposal record too (disposed_at, disposed_by, disposal_reason, disposal_notes), so the dashboard and the Claims section read the same rows.
  • claim_verifications stores one row per identity check: ID type, the last four characters of the ID number only (cleared after the retention period), result, the validating staff member and the database time.
